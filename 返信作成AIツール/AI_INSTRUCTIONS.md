# AIメールアシスタント 開発・保守ガイドライン

このドキュメントは、本プロジェクト（AIメールアシスタント）を今後AI（Cursor / Antigravity / Claude Code等）を用いて開発・改修する際の**「絶対的な指示書（システムプロンプト）」**として機能します。
AIエージェントは、本プロジェクトのコードを変更する前に必ずこのドキュメントを読み、以下の方針に従って実装を行ってください。

---

## 1. プロジェクト概要
*   **目的:** 顧客サポート（CS）や営業（お弁当デリ・社食DELIなど）における、お客様へのメール返信文作成をGemini APIを用いて自動化・効率化するツール。
*   **ターゲットユーザー:** 現場のCSスタッフ、営業スタッフ。非エンジニアが多く利用するため、使いやすさ・直感的なUI（ローディング時間を感じさせない等）を最優先する。
*   **主要な画面構成:**
    1.  `index.html` (app.js): 汎用返信（受信メールを元に返信を作成）
    2.  `create.html` (create.js): 汎用新規（ゼロから新規メールを作成）
    3.  `obento_cs.html` (obento_cs.js): お弁当デリCS専用（方針選択やFAQ等、CS特化のUI）
    4.  `prompts.html` (prompts.js): プロンプト置き場（社内でよく使う指示の共有ライブラリ）
    5.  `manual.html`: ユーザー向けマニュアル

## 2. 技術スタックとアーキテクチャ
*   **フロントエンド:** Vanilla JavaScript, HTML5, CSS3 (外部ライブラリはFontAwesomeのみ。React等のフレームワークは**使用しない**)
*   **スタイリング:** `style.css` におけるプレーンなCSS環境。モダンでクリーンなUI（ガラスモーフィズム、変数を用いたテーマカラー管理）を採用。
    *   **※CSS変更時の注意:** 既存のクラスネーム（`.panel`, `.form-group`, `.primary-btn` 等）の構造は極力変更・破壊せず、コンポーネントを再利用すること。
*   **バックエンド/API:**
    *   **LLM:** Google Gemini API (`streamGenerateContent`エンドポイントによる**SSEストリーミング出力**を標準とする)
    *   **DB / ログ基盤:** Google Apps Script (GAS) 経由でGoogle スプレッドシートへアクセス。プロンプトの読み込み、および利用ログ（logUsage）の送信に使用。

## 3. AIによる開発・改修時の「絶対ルール (MUST)」

1.  **フレームワークの導入禁止:**
    Vanilla JSで構成されているため、AI独自の判断でJQuery, React, Vue, Tailwind CSSなどを突然インポートしないでください。
2.  **ストリーミング出力の維持:**
    返信生成AIの核となるのは「待ち時間ストレスの排除」です。Geminiへのリクエストは必ず `streamGenerateContent` を使用し、UI（`#resSubject`, `#resBody`）へリアルタイムに文字を描画（typing）させるロジックを破壊しないでください。
3.  **GAS連携の保持:**
    `fetch` を用いてログやデータをGASへ送信する際、CORSエラーを回避するために `mode: 'no-cors'` が設定されている箇所があります。また、GETリクエスト時のコールバック処理（JSONPライク）の仕組みを変更しないでください。
4.  **プレースホルダー・UIテキストへの配慮:**
    ユーザーが「AIにどんな指示を書けばいいか」迷わないよう、テキストエリアの `placeholder` には箇条書きのテンプレート（例: `・伝える結論：` 等）を配置しています。これらのUIの工夫（UX向上施策）を誤って削除しないようにしてください。
5.  **安全なGit運用 (Claude Codeへの指示):**
    ターミナルで `claude` を使い直接コミット/プッシュさせる際は、作業開始時に新しいブランチ（例: `feature/xxx`）を切り、動作確認が完了してから `main` にマージさせる運用を推奨します。

## 4. 既存のストレージ（状態管理）
アプリケーションの設定値は `localStorage` に保存されています。
*   `geminiApiKey`: Gemini API キー
*   `staffName`: 担当者名（ログ送信・署名用）
*   `geminiSignature`: メールの末尾に付与する署名
*   `gasUrl`: バックエンド（GAS）のエンドポイントURL

## 5. 追加実装時のフロー
新しい機能を追加する際は、以下のステップを踏んでください。
1.  既存のコード（特に `app.js` の `streamGeminiApi` の書き方）を読み込む。
2.  HTMLにDOM（id属性付き）を追加し、CSSでスタイリングする。
3.  JS側でイベントリスナーを登録し、機能を実装する。
4.  実装後、必ず「待ち時間（ローディング）」や「エラー時の画面表示」のUXを考慮し、ユーザーが不安にならないUIフローを整えること。
